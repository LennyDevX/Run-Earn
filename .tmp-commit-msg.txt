## Security 🔒

**Seven response headers, all enforced.** The CSP started as `Report-Only` and
now blocks. It is built from the environment — `buildCsp()` reads the configured
RPC origins so switching providers cannot silently break the app.
`'unsafe-eval'` is development-only.

**Redis-backed rate limiting** on every route that costs money. `@vercel/kv` is
EOL, so this uses `@upstash/redis` + `@upstash/ratelimit` with an in-process
fallback. Sliding window, not fixed — a fixed window lets a caller burst 2x the
limit across a boundary.

The property that matters most: on `/api/generate-sneaker` the throttle runs
**before form parsing and before Gemini**. Verified by posting seven bodyless
requests — five returned 400 with **zero tokens spent**, the next two 429.

**A global daily spend budget** on top of the per-IP limits. Per-IP throttling
cannot stop a botnet spreading requests across thousands of addresses; a shared
cap can, because it does not care who is asking.

**`npm audit`: 29 findings with 1 critical -> 24 with 0.** Both Next.js advisories
were checked against this codebase before deciding urgency — the `next/og` RCE
and all nine September 2026 advisories are conditional on features Airen does not
use. Moved to 16.3.8 regardless.

## Performance ⚡

**`transition-all`: 61 -> 0.** Every one classified by what it actually changes
and replaced with an explicit property list. The `defi` page turned out to be
animating widths that never change — removed rather than "fixed".

**Progress bars moved to the compositor.** All 12 animated `width`, which
triggers layout and paint every frame. Now `transform: scaleX()` with
`origin-left`.

**RPC reads: ~60 -> ~2 per 20-NFT wallet.** `useOwnedSneakers` read three fields
per token, each its own round trip. All of it now goes through one `multicall`,
with `allowFailure` so a single unreadable token cannot sink the batch.

**`useOwnedSneakers` instances: 8 -> 1.** A new `SneakerOwnershipProvider` holds
one instance for the whole tree and exposes a pre-filtered `playable` list — so a
gameplay surface cannot forget to exclude collectibles.

**Skeletons replace text labels.** A label collapses to one line and then jumps
to a card grid; a skeleton with the shape of the real content reserves the space.
The shimmer animates `transform` only.

**`/mint` payload: 675 -> ~560 KiB.** Every showcase frame was absolutely
positioned over the same square, so all eight sat in the viewport at once and
`loading="lazy"` deferred nothing.

## Stability 🐛

**The `/mint` scroll on arrival.** `centerInScrollRow` used `scrollIntoView`,
which walks every scrollable ancestor including the document — so it moved the
page whenever the target sat below the fold. `/mint` was the only route calling
it on mount. Now it scrolls the row directly and can never move the page.

**A config bug that silently ate a cache directive.** The blanket
`Cache-Control: no-store` on `/api/*` in `next.config.ts` overrode whatever a
route handler set, so `/api/pol-price` could never cache. Each route now declares
its own policy.

**Two dead reads in `useWorkshop`.** `rarityBonus` and `nextForgeCost` were
removed from the ABI when forge was deleted, but the hook still read them inside
an unguarded `Promise.all` — the whole bonus snapshot was rejecting.

**The mint rarity bug.** The mint call passed the tier index (0-3) as the rarity
score and hardcoded tier 1, so every AI mint landed at rarity ~0.

## Dependencies 📦

`next` 16.3.8 (September 2026 security release) · `react` / `react-dom` 19.3.0 ·
`@types/react` / `@types/react-dom` 19.3.0 · `eslint-config-next` 16.3.8.

React 19.3's one breaking change was checked: `useId` now emits `_` instead of
`:` in generated IDs. `MoreSheet` is the only consumer and uses the values purely
as `aria` attributes, never as a CSS selector.

**TypeScript 7 is deliberately not adopted.** 7.0 ships no programmatic compiler
API and `typescript-eslint` hard-crashes at module load on it. Blocked until 7.1
— `tsconfig.json` is already 7-ready when it lands.
